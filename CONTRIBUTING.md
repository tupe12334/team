# Contributing to team

## Architecture

`team` is a polyglot monorepo. The daemon owns the queue and dispatches work; everything else is a client.

```
┌──────────────────────────────────────────────────────────┐
│                   Daemon (Rust · Tonic gRPC)             │
│                                                          │
│  ┌─────────────────┐    ┌─────────────────────────────┐  │
│  │  Centy Poller   │    │        Queue (JSON)         │  │
│  │  (every 30 s)   │───▶│  QUEUED → RUNNING → DONE   │  │
│  └─────────────────┘    └──────────────┬──────────────┘  │
│                                        │                  │
│                          ┌─────────────▼──────────────┐  │
│                          │       Worker Pool           │  │
│                          │  picks highest-priority     │  │
│                          │  QUEUED task, respects      │  │
│                          │  workers_count concurrency  │  │
│                          └─────────────┬──────────────┘  │
└────────────────────────────────────────┼─────────────────┘
                                         │ worktree open <ref>
                                         │ TEAM_AGENT=<agent>
                                         ▼
                                    worktree-io
                              (post:open hook → gstack skill)
```

**Clients** all speak gRPC to the daemon:

| Client | Location | Notes |
|--------|----------|-------|
| Web UI | `client/` | Next.js 16, React 19, API routes proxy to daemon |
| CLI | `cli/` | Go, generated by `protoc-gen-cobra` |
| MCP server | `mcp/` | Go, exposes daemon as MCP tools |
| TUI | `tui/` | Rust, ratatui |

## Repository layout

```
proto/          Protocol Buffer definitions (source of truth for all APIs)
daemon/         Rust gRPC server
  src/
    main.rs             Entry point; starts worker pool + Centy poller
    state.rs            AppState: config, queue (JSON persistence), workers
    worker_pool.rs      Async dispatch loop; spawns worktree subprocess
    centy_poller.rs     Auto-enqueues Centy "in queue" issues every 30 s
    gstack_agents.rs    Static list of all 35 gstack skill names
    link_resolver.rs    Resolves GitHub/Jira/Centy URLs to IssueRef
    issue_ref_json.rs   Serde for queue.json persistence
    services/           Tonic gRPC service implementations
cli/            Go gRPC client (generated)
mcp/            Go MCP server (generated)
client/         Next.js web UI
  src/
    app/api/    Next.js API routes (thin proxy to daemon via gRPC)
    components/ React components + custom hooks
    gen/        Generated TypeScript proto bindings (do not edit)
    lib/grpc/   gRPC client singletons + typed wrapper functions
tui/            Rust terminal UI (ratatui)
```

## Prerequisites

- **Rust** 1.85+ — `curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh`
- **Go** 1.26+
- **Node.js** 20+ with **pnpm** — `npm i -g pnpm`
- **buf** (proto toolchain) — `brew install bufbuild/buf/buf`
- **protoc-gen-cobra** — `go install github.com/NathanBaulch/protoc-gen-cobra@latest`
- **protoc-gen-go-mcp** — `go install github.com/redpanda-data/protoc-gen-go-mcp/cmd/protoc-gen-go-mcp@latest`
- **ts-proto** — installed via `pnpm install` in the repo root
- **worktree-io** — `worktree` binary must be in PATH for task execution

## Local setup

```bash
# 1. Copy the environment file
cp .env.example .env          # set DAEMON_PORT (default 50051)

# 2. Install JS dependencies (required for proto code generation)
pnpm install

# 3. Build everything (runs proto generation first, then compiles all components)
make build

# 4. Run daemon + web UI together
make run
# Then open http://localhost:3000
```

For the web UI to connect when running standalone (not via `make run`):

```bash
cp client/.env.example client/.env  # DAEMON_PORT=50051
pnpm --prefix client dev
```

## Development workflow

```bash
make lint    # proto generation + go vet (CLI + MCP), cargo clippy (daemon + TUI), ESLint
make test    # proto generation + tsc --noEmit, Vitest (146 tests), cargo test (175 daemon + 22 TUI tests)
make build   # proto generation + compile CLI, MCP, daemon, TUI, Next.js
```

All three automatically run `make generate` first (so proto bindings are always fresh). All three run on every `git push` via the Husky pre-push hook.

## Proto changes

Proto definitions live in `proto/`. After editing:

```bash
make generate   # runs buf generate + patches protoc-gen-cobra quirk
```

Generated outputs:
- `cli/gen/` — Go gRPC client + CLI commands (protoc-gen-cobra)
- `mcp/` — Go MCP bindings (protoc-gen-go-mcp)  
- `client/src/gen/` — TypeScript bindings (ts-proto)

Do not hand-edit generated files.

## Adding a gstack agent

The available agents are a static list in `daemon/src/gstack_agents.rs`. Each entry is:

```rust
AgentDef { name: "my-skill", description: "What this skill does." },
```

The name must match the gstack skill directory name. After adding:
1. Update `daemon/src/gstack_agents.rs::tests::all_returns_35_agents` count
2. Run `cargo test` to verify

## Code style

- **Rust**: `cargo fmt` + `cargo clippy -- -D warnings` before committing
- **Go**: `go vet ./...`
- **TypeScript**: ESLint (`pnpm lint`) + `tsc --noEmit`
- Pre-commit hook runs `cspell` — add new domain terms to `cspell.json`
- Tests live alongside code in `#[cfg(test)]` modules (Rust) or `.spec.ts` files (TypeScript)
